# chuo 要件定義書

chuo は、クロスプラットフォームで動作し、容易に拡張できるモジュール（プラグイン）システムを持つランチャーアプリである。

- FlowLauncher との差別化：Windows 以外（Linux）でも動作する
- ueli との差別化：本体を再ビルドせずに、本体とは独立してプラグインを追加・更新できる

## 0. 前提と判断基準

- **個人で使うアプリ**であり、プラグインも基本的に作者自身が作る。
- 配布のしやすさ、多言語対応、厳密なサンドボックスよりも、**作りやすさとメンテナンスのしやすさ**を優先する。
- **常駐リソースの小ささ**と、**ホットキーを押してから表示されるまでの速さ**を重視する。

## 1. 対応プラットフォーム

| 優先度 | 環境 | 備考 |
|---|---|---|
| **最優先** | Windows | 最もよく使う環境 |
| 優先（挑戦） | Linux の GNOME（Wayland） | 作者が使っている Fedora Workstation の環境。同梱する GNOME Shell 拡張で対応する（「3.6 GNOME Shell 拡張」を参照）。実現が困難だと判明した場合は、**対応を諦めることも許容する** |
| 次点 | Linux の X11、Wayland の KDE / wlroots 系 | プラットフォーム層の構造だけ用意しておき、実装は後回しにする（X11 は `XGrabKey` と XFixes、Wayland はポータルの `GlobalShortcuts` と data-control） |
| オプション | macOS | CI でのビルド確認のみ行い、動作はベストエフォート |

- macOS 固有の API に依存する機能はコア機能にしない。
- Windows でのみ実現できる機能は許容する。ただし、Windows 専用の機能のためにコアの設計を歪めない。

## 2. 技術スタック

| 項目 | 採用するもの |
|---|---|
| ランタイム | .NET 10（LTS） |
| UI | Avalonia（その時点の最新安定版） |
| 本体の構成 | 汎用ホスト（`Microsoft.Extensions.Hosting`） |

## 3. プラグインシステム

### 3.1 方式

- プラグインは **C# のクラスライブラリ（アセンブリ）** とする。
- プラグインごとに collectible な `AssemblyLoadContext`（ALC）で読み込み、プラグイン単位でアンロードやホットリロードができるようにする。
- ホスト側の ALC と共有するアセンブリは、`Chuo.Abstractions` と `Microsoft.Extensions.*` に限る。それ以外の依存（NuGet 由来など）は、プラグインのフォルダ内のものをそのプラグインの ALC の中でだけ解決する。

### 3.2 信頼モデル

- プラグインは**信頼する前提**とし、API の制限やサンドボックスは設けない。
- 要件は**「意図しないプラグインが読み込まれないこと」**のみとする。

| 種別 | 置き場所 | 読み込みの条件 |
|---|---|---|
| 同梱プラグイン | 本体のフォルダの `plugins/` | ビルド時に埋め込んだハッシュと一致すること |
| ユーザーが追加したプラグイン | データフォルダの `plugins/` | 承認リストに記録された「プラグイン ID＋フォルダ全体のハッシュ」と一致すること |
| 開発中のプラグイン | 設定画面で明示的に登録したパス | ハッシュは検証しない。ホットリロードを有効にする |

- 新しく見つかったプラグインや、内容が変更されたプラグインは「未承認」として通知する。`chuo plugin trust <id>` または UI 上の通知から承認したときに、承認リストに記録する。
- `chuo plugin add <フォルダ>` で、データフォルダへのコピーと承認をまとめて行う。
- プラグインを取得するためのレジストリやストアは作らない。

### 3.3 メタデータ

**パッケージの身元情報**は `plugin.json` に書く。承認時の表示や互換性チェックは、コードを実行せずにこのファイルで行う。

```json
{
  "id": "chuo.files",
  "name": "File Search",
  "version": "1.0.0",
  "entry": "Chuo.Plugins.Files.dll",
  "hostApi": "1.x"
}
```

- `hostApi` がホスト API のバージョンと合わないプラグインは読み込まない。

**機能の定義**はコードの属性で行う。1つのプラグインに複数のプロバイダを含められる。

```csharp
[CatalogProvider(Keyword = "f", IncludeInGlobal = false)]
public sealed class FileCatalog : ICatalogProvider { ... }

[LiveQueryProvider(Keyword = "=", GlobalTrigger = @"^[\d\s+\-*/().]+$")]
public sealed class Calculator : ILiveQueryProvider { ... }
```

- ライブクエリ型のインターフェイスは `ILiveQueryProvider` とする（`IQueryProvider` だと、暗黙の using に含まれる `System.Linq.IQueryProvider` と名前が衝突するため）。

- 属性で指定したキーワードなどは**既定値**であり、ユーザーが設定画面で上書きできる。

### 3.4 構成方法とライフサイクル

- 本体は汎用ホストで構築する。
- プラグインごとに、専用の ALC の中で**ミニ汎用ホスト**（`Host.CreateEmptyApplicationBuilder`）を作る。

```csharp
public sealed class ClipboardPlugin : IChuoPlugin
{
    public void ConfigureServices(IServiceCollection services, IPluginContext ctx)
    {
        services.AddSingleton<ClipboardStore>();
        services.AddHostedService<ClipboardWatcher>();
        services.Configure<ClipboardOptions>(ctx.Configuration);
    }
}
```

- プロバイダは、ホストが属性をスキャンし、プラグインの子コンテナから生成する。プロバイダはコンストラクタで依存を受け取れる。
- 常駐処理は `IHostedService` / `BackgroundService` で書く。
- 本体のサービス（`IClipboard`、`ILauncher`、`IShell`、`IPluginStorage`、`ILogger<T>` など）は、プラグインのホストにインスタンスを中継して登録する。
- アンロードは `StopAsync()`、`Dispose()`、`ALC.Unload()` の順に行う。
- プラグインの設定は `settings.json` の `plugins.<id>` のセクションを `IConfiguration` として渡し、`IOptionsMonitor<T>` で即座に反映する。
- プラグインの設定画面は、ホストが Options クラスから自動で生成する（「10.2 プラグインの設定画面」を参照）。

### 3.5 開発体験

- `dotnet new chuo-plugin` のテンプレートを用意する。
- デバッグは、開発モードのパスを登録し、chuo のプロセスにアタッチして行う。プラグインを保存するとビルドされ、ホットリロードされる。

### 3.6 GNOME Shell 拡張（GNOME 用のプラットフォーム層）

GNOME の Wayland では、アプリ側からはホットキーの登録、フォーカスの取得、ウィンドウの位置決め、クリップボードの監視ができない（または不確実である）。そこで、chuo に同梱する GNOME Shell 拡張に、GNOME Shell の内部でしかできない処理だけを任せる。

| 役割 | 拡張の中で使う API |
|---|---|
| グローバルホットキー | `Main.wm.addKeybinding` |
| ウィンドウの前面化とフォーカス | `Main.activateWindow` |
| ウィンドウの位置（マウスのあるモニタの中央など） | `MetaWindow.move_frame` |
| クリップボードの監視 | `St.Clipboard` と selection の変更イベント |

- 本体との通信は D-Bus で行う（本体側は `Tmds.DBus`）。
- 拡張は JavaScript で書く。C# だけで作るという方針の**唯一の例外**とし、ロジックはすべて C# 側に置く。拡張はイベントの中継と GNOME Shell の API 呼び出しだけを行う。
- GNOME のメジャー更新（約半年ごと）に追従する保守コストがかかるため、拡張の役割は上の表の範囲に限定する。
- `chuo install` は、GNOME の環境では拡張のインストールと有効化も行う。
- **リスク：** 実現が困難な場合や保守コストが見合わない場合は、GNOME の Wayland への対応を諦めることも許容する（「1. 対応プラットフォーム」を参照）。

## 4. 検索モデル

検索はカタログ型とライブクエリ型の 2 種類のプロバイダによるハイブリッド方式とする。

### 4.1 カタログ型

- 対象：アプリ、ファイル、クリップボード履歴など、項目の一覧を事前に作れるもの。
- プラグインは項目（`CatalogItem`）をホストに登録するだけで、検索はホストがメモリ上のインデックスに対して行う。
- 項目の更新は、プラグインが任意のタイミング（起動時、ファイル変更の監視時、定期実行時など）でホストに通知する。
- 属性 `IncludeInGlobal` で、全体検索に含めるか、キーワードを付けたときだけ検索対象にするかを指定する。

### 4.2 ライブクエリ型

- 対象：電卓、Web 検索など、入力に応じて結果を動的に作るもの。
- 基本はキーワードを指定したときだけ呼ばれる。
- `GlobalTrigger`（正規表現）を宣言した場合は、入力が一致したときだけ全体検索にも参加する。
- `CancellationToken` を必須とし、キー入力ごとに前のクエリをキャンセルする。タイムアウトも設ける。

### 4.3 順位付け

- 順位付けはホストが一括で行う。ファジーマッチと使用履歴（項目を実行した回数や新しさ）を組み合わせる。
- 優先順位は次のとおりとする。

  **エイリアスの完全一致（最上位に固定）＞ エイリアスの前方一致（大きく加点）＞ お気に入り（強く加点）＞ 通常の項目**

- 1つのエイリアスに複数の項目が一致した場合は、それらを使用履歴の順に並べる。

### 4.4 日本語の検索

- ひらがなとカタカナ、全角と半角を同一視して検索する。
- **ローマ字で検索できる**ようにする（例：`memo` で「メモ帳」、`dentaku` で「電卓」に一致）。
  - カタログに項目を登録するときに、ホストが形態素解析で読み（かなとローマ字）を付与する。
  - プラグインは `Keywords` で読みや別名を明示的に渡すこともできる。
- 辞書のメモリへの影響は、試作の段階で計測する。大きすぎる場合は、読みを SQLite にキャッシュし、辞書を常駐させない。
- **IME の制御：** ランチャーを開いたときに IME をオフにできるようにする（設定 `ime.offOnShow`、既定は `true`）。ローマ字での検索と組み合わせて、IME を切り替えずに打てることを狙う。
  - Windows では IMM32（`ImmSetOpenStatus`）または TSF を使って、自分のウィンドウの入力コンテキストだけを制御する。
  - Linux では IBus（Fedora の既定）と Fcitx5 を D-Bus 経由で制御する。具体的な方式（入力コンテキストごとの制御か、Avalonia の入力目的のヒントを使うか）は試作で検証する。
  - ランチャーを閉じたときに、元の IME の状態に戻すかどうかも試作で決める。

## 5. 呼び出しとレイテンシ

- 本体は常駐させる。ウィンドウは起動時に生成し、閉じるときは破棄せずに隠すだけにする。
- グローバルホットキーの登録、ウィンドウの前面化とフォーカスは、環境ごとに次の方法で行う。

| 環境 | ホットキー | 前面化とフォーカス | 対応時期 |
|---|---|---|---|
| Windows | `RegisterHotKey` | `SetForegroundWindow`（ホットキー経由の呼び出しなので許可される） | 初版 |
| GNOME（Wayland） | 同梱の GNOME Shell 拡張（`Main.wm.addKeybinding`） | 同梱の GNOME Shell 拡張（`Main.activateWindow`） | 初版（挑戦） |
| Linux X11 | `XGrabKey` | `_NET_ACTIVE_WINDOW` | 後回し |
| Wayland（KDE / wlroots 系） | XDG Desktop Portal の `GlobalShortcuts` | 未定 | 後回し |

- 拡張が無効な場合やポータルに非対応の環境では、デスクトップ環境の設定でショートカットを作り、`chuo toggle` を呼んでもらう（予備手段）。
- **`chuo` コマンド**は NativeAOT でビルドした軽量クライアントとする。IPC（`NamedPipeServerStream`。Windows では名前付きパイプ、Unix ではドメインソケットとして動く）で本体にコマンドを送る。
  - 本体は1つだけ常駐させる。2つめ以降に起動された `chuo` は、コマンドを送る側として動いて終了する。
  - コマンドの例：`toggle`、`show --query "f "`、`config`（設定画面を開く）、`install`、`plugin add` / `plugin trust`、`bench`
- **非機能要件：** ホットキーを押してから、ウィンドウが表示されて入力を受け付けるまで **50ms 以内**（暫定の目標）。`chuo bench` で計測し、実際に使いながら見直す。

## 6. 結果の項目とアクション

### 6.1 項目の識別

- `ResultItem.Id` を必須にする。プラグイン内で一意で、再起動しても変わらない値とする（例：`.desktop` のパス、AppUserModelID、ファイルのフルパス）。
- グローバルな識別子は `<pluginId>:<itemId>` とする。使用履歴、エイリアス、お気に入り、無視の設定で共通に使う。

### 6.2 アクション

- 項目はアクションのリストを持つ。
  - 先頭のアクションが既定で、Enter で実行される。
  - 2つめ以降のアクションは、修飾キー（例：Ctrl+Enter）に割り当てられる。
  - Tab または → でアクションパネルを開き、一覧から選んで実行することもできる。
- ホストは標準のアクション（開く、フォルダを表示、テキストのコピー、URL を開くなど）を提供する。プラグインは独自のアクションも定義できる。
- アクションを実行した後の振る舞いは、アクションごとに指定する。

| 振る舞い | 説明 |
|---|---|
| ランチャーを閉じる | 既定 |
| 開いたままにする | 続けて操作したいときに使う |
| 入力欄の文字列を書き換える | フォルダの中に入るような、掘り下げ型の操作に使う |

- アクションの実行は使用履歴に記録し、順位付けに反映する。

## 7. 項目ごとのユーザー設定（エイリアス、お気に入り、無視）

項目ごとのユーザー設定は `items.json` にまとめて保存する。アプリが書き換えるファイルであり、手で編集することもできる。手で編集した場合は自動で再読み込みする。

```json
{
  "chuo.apps:firefox.desktop": { "aliases": ["ff", "web"], "favorite": 1 },
  "chuo.apps:uninstall-foo.desktop": { "ignore": true }
}
```

- `favorite` はお気に入りの表示順を表す。
- 登録はランチャーの画面の中（アクションパネルやショートカットキー）で行う。設定画面の「項目」のページでも、エイリアス、お気に入り、無視の一覧を確認し、編集や削除ができる。

### 7.1 エイリアス

- アクションパネルの「エイリアスを設定」から登録する。
- 順位付けでの扱いは「4.3 順位付け」のとおり。
- 範囲外：入力した文字列を別の文字列に展開するようなクエリのマクロ機能。

### 7.2 お気に入り

- 追加と並べ替えはランチャーの画面の中で行う。設定画面でも一覧で確認し、並べ替えや削除ができる。

| 操作 | 方法 |
|---|---|
| 追加・削除 | アクションパネル、または Ctrl+D |
| 並べ替え | 入力が空のときのお気に入りの一覧で、Alt+↑ / Alt+↓ |

- 入力が空のときは、お気に入りを指定した順に表示し、その下に最近使った項目を表示する。
- 検索時は順位付けで強く加点する。

### 7.3 無視

- アクションパネルの「無視する」で、項目を ID 単位で除外する。
- 設定画面で glob パターン（例：`chuo.apps:*uninstall*`）を登録して、まとめて除外することもできる。
- 無視の判定はホストが行い、カタログ型とライブクエリ型の両方の結果に適用する。
- `:ignored` の一覧で無視した項目を確認でき、アクションパネルの「無視を解除」で元に戻せる。

## 8. MVP（初版）の機能

| # | 機能 | 種別 | 備考 |
|---|---|---|---|
| 1 | アプリ起動 | カタログ（全体検索に含める） | Windows はスタートメニューの `.lnk`、Linux は `.desktop` からアプリを列挙し、アイコンも取得する |
| 2 | 電卓 | ライブクエリ（グローバルトリガー） | |
| 3 | Web 検索 | ライブクエリ（キーワード） | 例：`g rust` |
| 4 | ファイル検索 | カタログ（`f` キーワードを付けたときのみ） | 詳細は 8.4 |
| 5 | クリップボード履歴 | カタログと常駐処理 | 詳細は 8.5 |

- 初版に含めない機能：システムコマンド、ウィンドウ切り替え、シェルコマンドの実行、スニペット。

### 8.4 ファイル検索

- 対象は設定画面で指定したフォルダだけとし、自前のインデックスを持つ。
- 起動時にスキャンし、その後は `FileSystemWatcher` で差分を反映する。
- 既定の除外パターン：`.gitignore` の内容に従い、さらに `.git`、`node_modules`、`bin`、`obj` などを除外する。設定で追加や上書きができる。
- 既定では `f` キーワードを付けたときだけ検索対象とし、全体検索に含めるかどうかは設定で切り替えられる。
- システム全体の検索（Everything や `plocate` との連携）は、必要になったら追加プラグインとして対応する。

### 8.5 クリップボード履歴

- 履歴の項目を選ぶと、クリップボードにコピーするだけとする（自動貼り付けはしない）。
- クリップボードの監視方法は次のとおり。

| 環境 | 監視方法 | 対応時期 |
|---|---|---|
| Windows | `AddClipboardFormatListener` | 初版 |
| GNOME（Wayland） | 同梱の GNOME Shell 拡張から D-Bus で通知を受ける（「3.6 GNOME Shell 拡張」を参照） | 初版（挑戦） |
| Linux X11 | XFixes のイベント | 後回し |
| Wayland（KDE / wlroots 系） | data-control プロトコル | 後回し |

## 9. UI

- 画面は入力欄と結果の一覧（アイコン、タイトル、サブタイトル）で構成する。
- 選択している項目がプレビューを持つ場合だけ、右側にプレビューパネルを表示する。
- プレビューは宣言的なデータとして返し、描画はホストが行う。プラグインが UI のコントロールを返すことはしない。
  - 種類：`TextPreview`、`ImagePreview`、`FilePreview`、`PropertiesPreview`
  - プレビューは項目を選択したときに初めて取得する（`Func<CancellationToken, Task<Preview>>`）。
- テーマは OS のライト／ダークの設定に従い、設定画面で上書きできる。
- ウィンドウの表示位置、最大表示件数などは既定値を決めたうえで、設定で変更できるようにする。

## 10. 設定とデータ

| 種類 | ファイル | 編集方法 |
|---|---|---|
| 設定 | `settings.json` | 設定画面で編集する。手で編集することもでき、保存すると自動で再読み込みされる |
| 項目ごとのユーザー設定 | `items.json` | アプリが書き込む。手で編集することもできる |
| 使用履歴、承認リスト | SQLite | アプリのみが書き込む |
| ログ | `logs/` | アプリが書き込む。日ごとにファイルを切り替え、プラグインごとにカテゴリを分ける |

- アプリが設定ファイルを書き込むときは、一時ファイルに書いてから置き換える。自分の書き込みによる変更の通知では再読み込みしない。
- 手で編集するときの入力補完（JSON Schema）は初版では作らない。
- 保存場所は次のとおり。

| OS | 設定 | データ |
|---|---|---|
| Linux | `~/.config/chuo/` | `~/.local/share/chuo/` |
| Windows | `%APPDATA%\chuo\` | `%APPDATA%\chuo\` |

### 10.1 設定画面

- **すべての設定を設定画面で変更できるようにする**（ueli や Flow Launcher と同様）。設定ファイルを手で編集しないと変えられない設定は作らない。
- 開き方：ランチャーの `:settings`、ランチャーを開いているときの Ctrl+,、`chuo config`
- 設定画面はランチャーとは別のウィンドウとする。常駐するメモリを増やさないため、開いたときに生成し、閉じたら破棄する。
- 変更はその場で反映する（保存ボタンは置かない）。ホットキーの登録に失敗した場合など、反映できなかったときは画面に表示する。

| ページ | 内容 |
|---|---|
| 一般 | ホットキー、自動起動、テーマ、表示位置、最大表示件数、IME（`ime.offOnShow`） |
| プラグイン | 一覧、有効・無効、未承認のプラグインの承認、キーワードと全体検索に含めるかの上書き、各プラグインの設定（10.2） |
| 項目 | エイリアス、お気に入り、無視の一覧と編集、無視の glob パターン |
| 開発 | 開発中のプラグインのパスの登録 |

### 10.2 プラグインの設定画面

- プラグインは UI のコントロールを返さない（「9. UI」の原則と同じ）。ホストが Options クラスのプロパティと属性から画面を自動で生成する。
- 属性は `System.ComponentModel.DataAnnotations` を使う（`[Display(Name, Description, Order)]`、`[Range]` など）。フォルダやファイルの選択のように、標準の属性で表せないものは独自の属性を用意する。
- 対応する型：`bool`、数値、`string`、列挙型（選択肢として表示）、パス、それらのリスト
- プラグインは `ConfigureServices` で、設定画面に出す Options クラスを登録する。対応していない型のプロパティがある場合、ホストは読み込み時に警告を出す。

```csharp
public sealed class FileSearchOptions
{
    [Display(Name = "対象のフォルダ"), FolderPath]
    public List<string> Folders { get; set; } = [];

    [Display(Name = "全体検索に含める", Description = "オフにすると f キーワードを付けたときだけ検索する")]
    public bool IncludeInGlobal { get; set; }
}
```

## 11. 配布とインストール

- 本体は自己完結型のアーカイブ（zip / tar.gz）として配布し、GitHub Actions で生成する。
- `chuo install` で次の処理を行う。

| 処理 | Windows | Linux |
|---|---|---|
| 自動起動の登録 | `HKCU\...\Run` | `~/.config/autostart/chuo.desktop` |
| PATH への追加 | ユーザーの PATH に追加 | `~/.local/bin` にシンボリックリンクを作成 |
| アプリ一覧への登録 | — | `.desktop` を登録 |
| GNOME Shell 拡張 | — | GNOME の環境では、拡張をインストールして有効化する |

- 更新は初版では手動とする。設定とデータは本体のフォルダと分離しているので、上書きしても安全である。
- Flatpak や Snap は、サンドボックスのせいでアプリの列挙、ファイル検索、クリップボードの監視ができないため採用しない。

## 12. 品質

- **単体テスト：** 検索の順位付け、読みの付与、プラグインの読み込みと承認を対象とする。
- **レイテンシ：** `chuo bench` で計測する。
- **UI の E2E テスト：** 初版では作らない。
- **CI：** GitHub Actions で Windows と Linux をビルドしてテストする。macOS はビルドのみ行う。

## 14. 最初の作業（技術検証）

UI の技術選択に影響しうる不確定要素があるため、ソリューションの骨組みを作る前に技術検証（スパイク）を行う。

| # | 検証項目 | 環境 | 合格基準 |
|---|---|---|---|
| 1 | ホットキーから表示までの時間 | Windows、GNOME（Wayland） | 50ms 以内（目標） |
| 2 | 隠しておいたウィンドウを表示したときに、前面に出て入力欄にフォーカスが当たるか | Windows、GNOME（拡張経由） | 確実にフォーカスが当たる |
| 3 | 表示時に IME をオフにできるか | Windows（IMM32 / TSF）、GNOME（IBus） | オフにできる |
| 4 | GNOME Shell 拡張から D-Bus でクリップボードの変化を受け取れるか | GNOME | テキストと画像の変化を受け取れる |
| 5 | Avalonia のアプリが常駐したときのメモリ使用量 | Windows、Linux | 計測して記録する |
| 6 | 形態素解析の辞書を読み込んだときのメモリと、読みの付与にかかる時間 | 共通 | 計測して記録する |

- Windows の検証を先に行う（最もよく使う環境のため）。
- GNOME の検証で致命的な問題が見つかった場合は、GNOME の Wayland への対応を諦めるか、Linux 向けの UI の構成を見直すかを判断する。
