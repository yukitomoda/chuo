# chuo 要件定義書

chuo は、クロスプラットフォームで動作し、容易に拡張できるモジュール（プラグイン）システムを持つランチャーアプリである。

- FlowLauncher との差別化：Windows 以外（Linux）でも動作する
- ueli との差別化：本体を再ビルドせずに、本体とは独立してプラグインを追加・更新できる

この文書には要件だけを書く。実現方法は `docs/design.md`、プラグイン API は `docs/plugin-api.md` にある。

## 0. 前提と判断基準

- **個人で使うアプリ**であり、プラグインも基本的に作者自身が作る。
- 配布のしやすさ、多言語対応、厳密なサンドボックスよりも、**作りやすさとメンテナンスのしやすさ**を優先する。
- **常駐リソースの小ささ**と、**ホットキーを押してから表示されるまでの速さ**を重視する。
- 本体もプラグインも C#（.NET）で書く。

## 1. 対応プラットフォーム

| 優先度 | 環境 | 備考 |
|---|---|---|
| **最優先** | Windows | 最もよく使う環境 |
| 優先（挑戦） | Linux の GNOME（Wayland） | 作者が使っている Fedora Workstation の環境。実現が困難だと判明した場合は、**対応を諦めることも許容する** |
| 次点 | Linux の X11、Wayland の KDE / wlroots 系 | 初版では対応しない。後から対応を加えられるようにしておく |
| オプション | macOS | ビルドが通ることだけを確認し、動作はベストエフォート |

- macOS 固有の機能に依存する機能はコア機能にしない。
- Windows でのみ実現できる機能は許容する。ただし、Windows 専用の機能のためにコアの設計を歪めない。

## 2. プラグイン

### 2.1 拡張のしかた

- 本体を再ビルドせずに、本体とは独立してプラグインを追加・更新できる。
- プラグイン単位で、本体を再起動せずにアンロードや再読み込みができる。
- プラグインが使うライブラリが、本体や他のプラグインが使うものと衝突しない。
- 1つのプラグインに、複数の検索の対象（「3. 検索」を参照）を含められる。
- プラグインは、本体の機能（クリップボード、ランチャーの表示、ファイルや URL を開く、データの保存、ログなど）を使える。
- プラグインは、常駐する処理（クリップボードやファイルの変更の監視など）を持てる。
- プラグインが宣言したキーワードなどは**既定値**であり、ユーザーが設定画面で上書きできる。
- 本体のプラグイン API のバージョンと合わないプラグインは読み込まない。

### 2.2 信頼モデル

- プラグインは**信頼する前提**とし、API の制限やサンドボックスは設けない。
- 要件は**「意図しないプラグインが読み込まれないこと」**のみとする。

| 種別 | 読み込みの条件 |
|---|---|
| 同梱プラグイン | 本体と一緒に配布したときの内容から変わっていないこと |
| ユーザーが追加したプラグイン | ユーザーが承認したときの内容から変わっていないこと |
| 開発中のプラグイン | 設定画面で明示的に登録したもの。内容は検証せず、変更すると自動で再読み込みする |

- 新しく見つかったプラグインや、内容が変更されたプラグインは「未承認」として通知する。`chuo plugin trust <id>` または UI 上の通知から承認できる。
- 承認するときは、プラグインのコードを実行せずに、ID、名前、バージョンを表示する。
- `chuo plugin add <フォルダ>` で、プラグインの追加と承認をまとめて行う。
- プラグインを取得するためのレジストリやストアは作らない。

### 2.3 開発体験

- `dotnet new chuo-plugin` のテンプレートを用意する。
- 開発中のプラグインを登録し、chuo のプロセスにアタッチしてデバッグできる。プラグインを保存するとビルドされ、再読み込みされる。

## 3. 検索

### 3.1 検索の対象と呼び出し方

- 入力すると、すべてのプラグインの対象をまとめて検索する（全体検索）。
- 入力の先頭にキーワードを付けると、そのプラグインの対象だけを検索する（例：`f 議事録`、`g rust`）。
- プラグインごとに、全体検索に含めるか、キーワードを付けたときだけ検索するかを指定できる。
- 項目の一覧を事前に作れるもの（アプリ、ファイル、クリップボード履歴など）と、入力に応じて結果を作るもの（電卓、Web 検索など）の両方を扱える。
  - 入力に応じて結果を作るものは、入力が特定の形のとき（電卓なら数式）だけ、キーワードがなくても全体検索に結果を出せる。
  - 結果を作るのが遅いプラグインがあっても、入力を妨げない。新しく入力したら前の問い合わせを取り消し、時間がかかりすぎたものは打ち切る。

### 3.2 順位付け

- 順位はプラグインをまたいで一貫した基準で付ける。あいまいな一致と使用履歴（項目を実行した回数や新しさ）を組み合わせる。
- 優先順位は次のとおりとする。

  **エイリアスの完全一致（最上位に固定）＞ エイリアスの前方一致（大きく加点）＞ お気に入り（強く加点）＞ 通常の項目**

- 1つのエイリアスに複数の項目が一致した場合は、それらを使用履歴の順に並べる。

### 3.3 日本語の検索

- ひらがなとカタカナ、全角と半角を同一視して検索する。
- **ローマ字で検索できる**ようにする（例：`memo` で「メモ帳」、`dentaku` で「電卓」に一致）。
  - 読みは、プラグインが指定しなくても自動で付く。
  - プラグインが読みや別名を明示的に指定することもできる。
- **IME の制御：** ランチャーを開いたときに IME をオフにできるようにする（設定で切り替えられ、既定では有効）。ローマ字での検索と組み合わせて、IME を切り替えずに打てることを狙う。
  - 他のアプリの IME の状態は変えない。

## 4. 呼び出しとレイテンシ

- 本体は常駐する。グローバルホットキーでランチャーを表示し、表示したときは前面に出て入力欄にフォーカスが当たる。
- ホットキーを登録できない環境では、デスクトップ環境の設定でショートカットを作り、`chuo toggle` を呼んでもらう（予備手段）。
- **`chuo` コマンド**で本体を操作できる。
  - 本体は1つだけ常駐する。2つめ以降に起動された `chuo` は、本体にコマンドを送って終了する。
  - コマンドの例：`toggle`、`show --query "f "`、`config`（設定画面を開く）、`install`、`plugin add` / `plugin trust`、`bench`
- **非機能要件：** ホットキーを押してから、ウィンドウが表示されて入力を受け付けるまで **50ms 以内**（暫定の目標）。`chuo bench` で計測し、実際に使いながら見直す。

## 5. 結果の項目とアクション

### 5.1 項目の識別

- 使用履歴、エイリアス、お気に入り、無視の設定は項目ごとに記録し、chuo やプラグインを再起動しても引き継がれる。

### 5.2 アクション

- 項目はアクションのリストを持つ。
  - 先頭のアクションが既定で、Enter で実行される。
  - 2つめ以降のアクションは、修飾キー（例：Ctrl+Enter）に割り当てられる。
  - Tab または → でアクションパネルを開き、一覧から選んで実行することもできる。
  - 項目を右クリックすると、アクションと、お気に入りや無視の操作をメニューから選べる。
- 標準のアクション（開く、フォルダを表示、テキストのコピー、URL を開くなど）を用意する。プラグインは独自のアクションも定義できる。
- Windows では、アプリを管理者として実行できる。Ctrl+Shift+Enter か、右クリックのメニューから選ぶ。
- アクションを実行した後の振る舞いは、アクションごとに指定する。

| 振る舞い | 説明 |
|---|---|
| ランチャーを閉じる | 既定 |
| 開いたままにする | 続けて操作したいときに使う |
| 入力欄の文字列を書き換える | フォルダの中に入るような、掘り下げ型の操作に使う |

- アクションの実行は使用履歴に記録し、順位付けに反映する。

## 6. 項目ごとのユーザー設定（エイリアス、お気に入り、無視）

- 登録はランチャーの画面の中（アクションパネル、右クリックのメニュー、ショートカットキー）で行う。設定画面の「項目」のページでも、エイリアス、お気に入り、無視の一覧を確認し、編集や削除ができる。
- 項目ごとのユーザー設定はファイルに保存し、手で編集することもできる。手で編集した場合は自動で再読み込みする。

### 6.1 エイリアス

- アクションパネルの「エイリアスを設定」から登録する。1つの項目に複数のエイリアスを付けられる。
- 順位付けでの扱いは「3.2 順位付け」のとおり。
- 範囲外：入力した文字列を別の文字列に展開するようなクエリのマクロ機能。

### 6.2 お気に入り

- 追加と並べ替えはランチャーの画面の中で行う。設定画面でも一覧で確認し、並べ替えや削除ができる。

| 操作 | 方法 |
|---|---|
| 追加・削除 | アクションパネル、右クリックのメニュー、または Ctrl+D |
| 並べ替え | 入力が空のときのお気に入りの一覧で、Alt+↑ / Alt+↓ |

- 入力が空のときは、お気に入りを指定した順に表示し、その下に最近使った項目を表示する。
- 検索時は順位付けで強く加点する。

### 6.3 無視

- アクションパネルか右クリックのメニューの「無視する」、または Ctrl+Delete で、項目を1つずつ除外する。
- 設定画面で glob パターンを登録して、まとめて除外することもできる。
- 無視は、すべてのプラグインの結果に適用する。
- `:ignored` の一覧で無視した項目を確認でき、「無視を解除」または Ctrl+Delete で元に戻せる。

## 7. MVP（初版）の機能

| # | 機能 | 全体検索 | 備考 |
|---|---|---|---|
| 1 | アプリ起動 | 含める | Windows はスタートメニュー、Linux はアプリ一覧に登録されたアプリ。アイコンも表示する |
| 2 | 電卓 | 数式を入力したときだけ | |
| 3 | Web 検索 | 含めない（キーワードのみ） | 例：`g rust` |
| 4 | ファイル検索 | 含めない（`f` キーワードのみ） | 詳細は 7.1 |
| 5 | クリップボード履歴 | | 詳細は 7.2 |
| 6 | フォルダのショートカット | 含める（設定で切り替え） | 詳細は 7.3 |

- 初版に含めない機能：システムコマンド、ウィンドウ切り替え、シェルコマンドの実行、スニペット。

### 7.1 ファイル検索

- 対象は設定画面で指定したフォルダだけとする。
- ファイルの追加、削除、名前の変更を自動で反映する。
- 既定の除外パターン：`.gitignore` の内容に従い、さらに `.git`、`node_modules`、`bin`、`obj` などを除外する。設定で追加や上書きができる。
- 既定では `f` キーワードを付けたときだけ検索対象とし、全体検索に含めるかどうかは設定で切り替えられる。
- システム全体の検索（Everything や `plocate` との連携）は、必要になったら追加プラグインとして対応する。

### 7.2 クリップボード履歴

- 履歴の項目を選ぶと、クリップボードにコピーするだけとする（自動貼り付けはしない）。
- 初版で対応する環境は Windows と GNOME（Wayland、挑戦）とする。Linux の X11 と、Wayland の KDE / wlroots 系は後回しにする。

### 7.3 フォルダのショートカット

- 設定画面で指定したフォルダの中にある、ショートカットと実行ファイル（Windows では `.lnk`、`.url`、`.exe`、`.bat`、`.cmd`）を検索して起動できる。
- サブフォルダも対象にするかは、フォルダごとに設定で切り替えられる（既定は対象にする）。
- フォルダの中のファイルの追加や削除、設定の変更は自動で反映する。
- 全体検索に含めるか、キーワードを付けたときだけ検索するかを、設定画面で切り替えられる。

## 8. UI

- 画面は入力欄と結果の一覧（アイコン、タイトル、サブタイトル）で構成する。
- 選択している項目がプレビューを持つ場合だけ、右側にプレビューパネルを表示する。
  - 種類：テキスト、画像、ファイル、プロパティの一覧
  - プレビューは項目を選択したときに初めて読み込む。
- 見た目はプラグインをまたいで統一する。
- テーマは OS のライト／ダークの設定に従い、設定画面で上書きできる。
- ウィンドウの表示位置、最大表示件数などは既定値を決めたうえで、設定で変更できるようにする。
- 画面が複数あるとき、ランチャーを表示する画面は、マウスカーソルのある画面（既定）かメインの画面かを選べる。

## 9. 設定とデータ

- 設定は JSON のファイルに保存する。手で編集することもでき、保存すると自動で再読み込みされる。手で編集するときの入力補完は初版では作らない。
- 使用履歴と承認したプラグインの記録はアプリだけが書き込む。
- ログをファイルに残す。日ごとにファイルを分け、どのプラグインのログかを区別できるようにする。
- 設定とデータは OS の慣習に従った場所に置き、本体のフォルダとは分ける。

### 9.1 設定画面

- **すべての設定を設定画面で変更できるようにする**（ueli や Flow Launcher と同様）。設定ファイルを手で編集しないと変えられない設定は作らない。
- 開き方：ランチャーの `:settings`、ランチャーを開いているときの Ctrl+,、`chuo config`
- 設定画面はランチャーとは別のウィンドウとする。
- 変更はその場で反映する（保存ボタンは置かない）。ホットキーの登録に失敗した場合など、反映できなかったときは画面に表示する。

| ページ | 内容 |
|---|---|
| 一般 | ホットキー、自動起動、テーマ、表示位置、最大表示件数、IME、ログのフォルダ（開く、パスのコピー） |
| プラグイン | 一覧、有効・無効、未承認のプラグインの承認、キーワードと全体検索に含めるかの上書き、各プラグインの設定（9.2） |
| 項目 | エイリアス、お気に入り、無視の一覧と編集、無視の glob パターン |
| 開発 | 開発中のプラグインの登録 |

### 9.2 プラグインの設定画面

- プラグインの設定も設定画面で変更できる。プラグインは画面を作らず、設定の項目を宣言するだけでよい。画面は本体が生成する。
- 設定の項目には、表示名、説明、並び順、値の範囲を指定できる。
- 扱える値：真偽値、数値、文字列、選択肢、フォルダやファイルのパス、それらのリスト
- リストの要素ごとに、複数の値を設定できる（例：対象のフォルダごとに、サブフォルダも対象にするか）。

## 10. 配布とインストール

- 本体は自己完結型のアーカイブ（zip / tar.gz）として配布する。展開するだけで動き、.NET のインストールは要らない。
- `chuo install` で次の処理を行う。
  - 自動起動の登録
  - `chuo` コマンドを使えるようにする（PATH への追加）
  - Linux では、アプリ一覧への登録
  - GNOME の環境では、動作に必要な GNOME Shell 拡張のインストールと有効化
- 更新は初版では手動とする。本体のフォルダを上書きしても、設定とデータは失われない。
- Flatpak や Snap は、サンドボックスのせいでアプリの列挙、ファイル検索、クリップボードの監視ができないため採用しない。

## 11. 品質

- **単体テスト：** 検索の順位付け、読みの付与、プラグインの読み込みと承認を対象とする。
- **レイテンシ：** `chuo bench` で計測する。
- **UI の E2E テスト：** 初版では作らない。
- **CI：** Windows と Linux をビルドしてテストする。macOS はビルドのみ行う。
